# Bare sleeps in the integration tests: the debt, and the ratchet that bounds it.
#
# A "bare" sleep is one that is NOT the poll interval of a wait - a guess at how
# long something takes, standing in for the condition the next line depends on.
# scripts/check-bare-sleeps.py fails if any count goes UP, if a file not listed
# here gains one, or if a count drops without this file being tightened.
#
# These are pre-harness tests that hand-spawn processes and have no observable to
# wait on. The fix for most of them is either await_port_accepting /
# await_log_matches (see tests/integration/await_port.hpp) or a move to
# cluster_harness.hpp. New tests should use the harness and add nothing here.
#
# count  path
#
# The remaining entries are not waits at all:
#  * test_postgres_pipeline's source sleeps ON PURPOSE to pace its emissions
#    (a deliberately slow producer is the fixture's point). The HA-standby
#    and CDC waits that used to sit here were converted 2026-08-10 - the
#    engine now announces standby entry, and the CDC test polls
#    pg_stat_replication for its walsender.
#  * test_soak's kill loop sleeps 5s between killing a worker and respawning
#    it ON PURPOSE: the gap is the scenario. A worker respawned instantly
#    into its old slot is item 46's path and a DIFFERENT test; the soak
#    wants the watchdog to declare the loss and the restart to land first,
#    and there is no observable for "the watchdog has not yet fired" to wait
#    on - the wait would be for the absence of an event. The 250ms and 10s
#    sleeps in the same file are poll/sample intervals the checker already
#    exempts; this is the one deliberate pause.
